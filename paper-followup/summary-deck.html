Evaluation protocol

All detectors are deterministic: fixed rules and statistics over logged data. Every verdict is exactly reproducible — no LLM-based scoring anywhere in the pipeline.

Detectors are tuned on a ~20% dev split (hash-based) and evaluated held-out only, with the same labels, splits and calibration as the published L0 baselines. Metric: detection rate at matched false-positive rate.

Detector inventory

Eleven detectors, three classes — plus a no-content baseline

D1–D3

Distribution-shift detectors

Per-run outlier score (leave-one-out likelihood) · sliding-window JSD + CUSUM change detection · block-level JSD profiles.

Requires: calibration data only. Identical code on every dataset.

D4–D9

Rule-based detectors

Hand-crafted features and heuristics: command-line rules, regex patterns over reasoning text, injection features, error signatures, prompt-diff attribution, first-error attribution.

Requires: feature engineering — and maintenance — per deployment.

D10

Consistency check

Cross-channel test: a tool-call error that the model's final answer never acknowledges.

Requires: matching tool calls to responses, per log format.

D11

Structural baselines

Position and sequence features only — no content read at all.

Requires: nothing. Twice, this baseline beat every content-based detector.

All detectors fixed before evaluation; all runs exactly reproducible. Labels D1–D11 as in the paper, §4.

Central result

More logging does not buy detection.
The detector class does.

Same input data — L1 command lines

Token-frequency detector (D1): 0.0% detection at every window size.
Rule-based detector (D4): 36–73% at ≤ 1.6% FPR.

And rules do not generalize

In-domain (tuning dataset): up to 99.7%.
On a second dataset (TRACE): 1.5–1.9% — chance level.

Why — the key distinction

One question predicts every result in this deck

A detector can find what a machine already wrote into the logs.
It cannot judge what only the outside world knows.

The failure leaves text in the logs → detectable

A crash leaves a stack trace, a failed command a non-zero exit code, an injection its own attack string. The detector only has to match text that is already there.

  • Every success in this deck is of this kind
  • But each needed hand-written rules, per deployment

Judging the failure needs outside knowledge → not detectable

Is the claim true? Was the link relevant? Did the plan match the user's intent? The answer is not in the logs — they hold at best weak correlates of it.

  • No tested detector beats chance at the same false-alarm budget
  • More logging (L1–L3) does not change this

Not a story told after the fact: applied to the two Who&When subsets before running anything, the rule predicted which one is solvable — and was right (30.9% top-1 vs content features at zero).

Real-world check — SWE-chat

Put to the test: 5,851 real sessions from 190 users

The method holds up, and per-user baselines are the right design —
but subtle real-world changes drown in normal user noise.

≈ 0

The lab protocol is valid

Stitched and real chronological timelines give the same false-alarm rates. The benchmark results were no lab artifact.

2.4×

Users are distinct individuals

Each user is 2.4× closer to their own past (JSD 0.149) than to anyone else (0.358) — one baseline per user is justified.

6×

Normal noise swamps the signal

Ordinary week-to-week variation (JSD ≈ 0.13) is 6× the detection threshold. A real CLI update vanishes in it.

2 wks

A frozen baseline expires fast

Drift from a user's first sessions reaches ~0.2 JSD within two weeks. The reference must keep updating.

JSD (Jensen–Shannon divergence): 0 = identical behavior, higher = more different. Source: paper §6.

Operating costs

What the working detectors cost to run

Content logging and rules are not a one-time buy — they charge four ongoing prices.
At realistic failure rates, most alarms would be false.

3–45×

Storage jumps a class

L0 metadata is already just ~1% of a raw transcript. Content logging multiplies that 3–45×, plus PII and redaction duties.

chance

Rules are a subscription

Hand-written rules must be redone as scaffold, task mix and language change. Carried to the next dataset unchanged, they scored at chance level.

4.5%

Other people's text sets off alarms

At L2 the detector reads third-party content. All of its false alarms were benign text that happened to look like instructions.

< 50%

In production, most alerts are wrong

Benchmarks use ~50% failures; reality is below ~5%. At that rate, precision drops under 50% — over half of all alarms are false.

4.5% is the injection detector's false-positive rate: the share of normal runs that trigger an alarm. Source: paper §5, §7.

Next steps

Three work streams, in order of expected impact

1 · SUPERVISED CLASSIFIERS

Fine-tuned BERT or gradient-boosted trees, weights fixed at inference

The untested middle ground: still fully reproducible (no test-time adaptation), and able to learn features that hand-crafted rules missed — the main blind spot.

First experiment: hallucination detection on AgentHallu and TRAIL, evaluated at matched FPR against D7/D10.

2 · ADAPTIVE BASELINES

Kalman filter / EWMA / Bayesian online change-point detection

Track the reference distribution instead of freezing it: model slow baseline evolution as state, alarm on residuals. Separates gradual variance from abrupt change.

Addresses: the 2-week staleness and the 6× variance floor — both measured. Improves the distribution-shift detectors only.

3 · BENCHMARK THE LLM JUDGE

Measure the alternative we excluded

Judge accuracy, cost per evaluation, run-to-run variance and version sensitivity — on the same datasets and splits.

Why: the build-vs-judge decision needs numbers on both sides; today only one side is measured.

Standing regression test alongside all three: apply every fixed detector unchanged to each new dataset — does it generalize? (Tested once so far; it did not.)

The limit that remains

Labels that require external ground truth cannot be computed from log features — by rules, Kalman filters or BERTs.

Learned models improve correlates and adaptive baselines reduce false alarms; neither supplies ground truth. What deterministic detection buys, measured: failures with machine-generated evidence, per deployment, for the lifetime of the rules. Everything beyond that line is an open measurement.

Next measurement that would change this deck: a fixed-weight classifier vs D10 on AgentHallu, at matched FPR.
